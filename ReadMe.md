🚀 K8sCacheApp — Демонстрация кэширования Redis с Kubernetes

Проект демонстрирует декларативное кэширование данных (@Cacheable) в приложении на Spring Boot 4 (Java 25) с использованием базы данных Redis в качестве распределенного кэша.
Главная особенность — архитектурное выравнивание под современные стандарты Jackson 3 / tools.jackson для безопасной бинарной сериализации сложных вложенных структур данных (включая Java Records, списки и энумы) без багов буферизации строк на новых версиях JDK.

🛠️ Что должно быть установлено (Prerequisites)

Помимо Java 25 и любимой IDE, на компьютере должны стоять:
1. Docker Desktop — для сборки образов и контейнеризации.
2. Minikube — локальный кластер Kubernetes (ставится через winget install Kubernetes.minikube).
3. Kubectl — консольная утилита для управления кластером (winget install Kubernetes.kubectl).

📂 Структура инфраструктурных файлов

Проект содержит папку k8s/ в корне со следующими манифестами:
• redis-deployment.yaml — разворачивает один под с базой данных redis:7-alpine.
• redis-service.yaml — создает внутреннюю сетевую службу k8scache-redis:6379, по имени которой Java-код находит кэш.
• app-deployment.yaml — разворачивает под с нашим Spring Boot приложением и связывает его с Redis через переменные окружения.
• app-service.yaml — открывает доступ к приложению извне кластера (через NodePort на порт 30080).

💻 Команды для быстрого запуска

Открой терминал (в Windows — PowerShell от Администратора) и выполни цепочку команд:
bash
# 1. Запуск локального кластера K8s на базе Docker
minikube start --driver=docker

# 2. Сборка Java-приложения на локальной машине (пропуская тесты)
mvn clean package -DskipTests

# 3. Сборка Docker-образа приложения
docker build -t k8scache-app:latest .

# 4. Импорт собранного образа внутрь виртуального окружения Minikube
minikube image load k8scache-app:latest

# 5. Развертывание всей инфраструктуры (Redis + App) одной командой
kubectl apply -f k8s/

# 6. Проверка статуса запуска подов (дождись статуса Running для обоих)
kubectl get pods

# 7. Проброс сетевого моста для доступа из Postman (запуск в фоне)
Start-Job -ScriptBlock { minikube service app-service --url }
Используйте код с осторожностью.

🎯 Как проверить работу

После запуска фоновой задачи (Start-Job) проверь адрес туннеля через команду Get-Job | Receive-Job или просто сделай HTTP-запрос в Postman:
text
GET http://127.0.0.1:<ПОРТ_ИЗ_ЛОГА_ТУННЕЛЯ>/orders/1  
Используйте код с осторожностью.  
• Первый клик: займет ~2 секунды (имитация тяжелой работы, данные пишутся в Redis).  
• Второй клик: отработает мгновенно (~15-20 мс), данные отдаются напрямую из пода кэша.
